# PPA-4978: Email Management: submitting an existing authentication id still tries to update email profile

**Type:** Bug · **Project:** Post Purchase Account · **Status:** Done
**Use as:** a good QA example, business-rule AC with testability baked in, plus test scenarios with evidence.

## Problem Statement
Users can get caught in a loop where the email address keeps changing across My Account pages.

## Impact Statement
Poor customer experience; email records drift between Nop and RTP, swapping back and forth as the user navigates.

## Acceptance Criteria
1. Move the customer-contact update in `contactapicontroller` to **after** the unity (auth) call.
2. **Create a new AQA test case** to ensure this bug does not return.
3. The Nop contact and customer tables are not updated to a new email until the RTP authentication-profile update succeeds.
4. The RTP email profile is only updated if the authentication-profile update succeeds.
5. When an email already in use as an authentication id is submitted, the "email already in use" error is shown, and **no** updates happen to RTP email/auth profiles or Nop contact/customer tables.
6. If a customer already has different account and communication emails (allowed in RTP) and an eligible email is submitted, both RTP profiles are updated to match and the Nop tables are updated.

## Test Scenarios (model for QA)

| Scenario | Setup | Expected | Result |
|---|---|---|---|
| Existing auth id does NOT update email profile (RequireEmailUsername=Y) | existing user, attempt to change to an in-use email | no update; error shown | PASS |
| Existing auth id does NOT update email profile (RequireEmailUsername=N) | same | no update; error shown | PASS |
| New auth id DOES update email profile (N) | submit a fresh, valid email | profiles updated and in sync | PASS |
| New auth id DOES update email profile (Y) | change back to a valid email | profiles updated and in sync | PASS |
