# QUAL-4510: a real test case (copy this format)

**Use as:** ✅ the QA shape to copy. This is a real exported test case in our **Action / Data / Expected Result** format. Match this structure and the [Test Case Standard](../standards/test-case-standard.md).

> Example feature: biometric login + minimum-age enforcement. Notice the steps are runnable by anyone, expected results are definitive, and the negative path (under-age login blocked) is tested explicitly.

| # | Action | Data | Expected Result |
|---|--------|------|-----------------|
| 1 | • Navigate to environment<br>• Create an account | | Account is created |
| 2 | • After the account is created and the user is signed in, log out<br>• Open the environment and log in again<br>• Log out again | | • User is logged out<br>• User is logged in<br>• User is logged out |
| 3 | • Navigate to environment, select "Sign In"<br>• Enter valid credentials (for the user you created)<br>• Continue | | Receive a screen offering to set up Biometrics, with: a title about logging in faster; instructions/information; a **Continue** button; a **Remind me later** button; a **Not on this device** link |
| 4 | Select Continue | | Prompted to set up biometrics |
| 5 | Select Continue | | User is logged in and directed to commerce |
| 6 | • Navigate to admin for the environment<br>• Go to Configuration > Setting > All Settings (advanced)<br>• Search for `customersettings.dateofbirthminimumage`<br>• Set this value to a number higher than the user's age (from step 1)<br>• Clear the cache and restart the application | | The value for the setting is updated and saved |
| 7 | • Navigate to the same environment<br>• Using biometrics, attempt to log in with the same user you created | | • An error message displays: **"This account does not meet the minimum age requirement."** *(editable language string)*<br>• User is not able to log in |

## Why this is a good model

- **Anyone could run it**: no author-only knowledge.
- **Definitive expected results**: "error message displays…", "user is not able to log in." No "should."
- **The negative path is the point**: it sets up a valid login, then proves the under-age block.
- Steps with multiple actions use **bulleted lists**, exactly as the standard requires.
